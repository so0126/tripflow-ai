# 리뷰 초안 생성 흐름 분석메모

## 1. 흐름 한 줄

```
CaptionSelect.vue (onMounted, 버튼 아님)
→ POST /ai/review/generate-styles?planId&reviewPostId
→ AiReviewController#generateStyles
→ AiReviewService#createAndSaveStyles (@Transactional, 동기)
→ ReviewStyleGenerateAgent#generateStyles (AI 호출)
→ aiReviewDao.insert (ai_review_analysis / ai_review_styles / ai_review_hashtags)
```

## 2. 관련 파일

**프론트**
- `CaptionSelect.vue` — 트리거(onMounted), isLoading, store 가드
- `src/api/travelgramApi.js` — generateAiStyles()

**백엔드**
- `AiReviewController.java` — 진입점 (@PostMapping /generate-styles)
- `AiReviewService.java` — createAndSaveStyles, @Transactional
- `ReviewStyleGenerateAgent.java` — 실제 AI 호출 (ChatClient)
- `AiReviewDao.java` — analysis/style/hashtag insert
- `ReviewPostDao.java` — mood, type 조회

## 3. 위험 지점

**H1. 멱등성 없음** (우선순위 1)
- reviewPostId 기준 기존 결과 체크 없음
- 새로고침·재진입마다 AI 재호출 + analysis 행 중복 누적
- ai_review_analysis.review_post_id에 UNIQUE 제약 없음

**H1 판단 (해결됨)**
- 접근: Service 레이어 가드. `createAndSaveStyles` 진입 시 `selectLatestAnalysisByReviewPostId`로 최신 analysis 1건 조회, 있으면 styles/hashtags 조립해서 그대로 반환. AI 호출/insert 분기 진입 X.
- "최신 1건" 정책: `ORDER BY created_at DESC, id DESC LIMIT 1`. 기존에 중복 누적된 행이 있어도 가장 최근 결과를 보여줌. H1 적용 후엔 사실상 1건으로 고정.
- UNIQUE 제약 보류: "재생성" 기능 가능성을 살려두기 위함. UNIQUE를 걸면 재생성 시 DELETE+INSERT 패턴이 강제됨. 대신 race condition (동시 요청 시 TOCTOU)은 감수 — 1인 화면 + onMounted 1회 트리거라 실제 발생 빈도 낮다고 판단.
- N+1 수용: 가드 안 조회가 analysis(1) + styles(1) + hashtags(N). resultMap collection 매핑으로 단일 JOIN 쿼리화 가능했으나, MyBatis 마법(columnPrefix/autoMapping)이 가독성을 크게 해쳐 보류. style 평균 5개 규모에서는 실질 병목 아님.
- 새로고침 UX: 별도 설계 없이 가드만으로 해결. 동일 응답이 다시 내려가므로 프론트는 첫 호출과 동일하게 렌더링.
- 변경 파일: `AiReviewDao` (메서드 시그니처 1개), `AiReviewAnalysisMapper.xml` (쿼리 1개), `AiReviewService.createAndSaveStyles` (가드 블록).

**H2. 실패 흔적 없음** (우선순위 2)
- AI 실패 시 @Transactional 롤백 → DB 흔적 0
- 상태 컬럼 없음 (review_posts, ai_review_analysis 모두)
- 프론트 catch 없음 → 실패해도 빈 화면만, 에러 메시지 없음

**M1. @Transactional 안 동기 AI 호출** (이번 스프린트 제외)
- AI 응답 대기 동안 DB 커넥션 점유
- 부하 시 커넥션 풀 고갈 가능
- 구조 변경 필요 → 4주 로드맵으로

**M2. 응답시간/token 로깅 없음**
- .call().content()만 사용, ChatResponse metadata(token usage) 버림
- AI 호출 시간 측정 없음

**L1. 실패 로그에 식별자 없음 + cause 유실**
- log.error("Style Generation Failed", e) 에 reviewPostId 없음 → 어떤 리뷰가 실패했는지 모름
- throw new RuntimeException("...") 이 원본 e를 cause로 안 넘김
- H2 해결할 때 같이 묶어서 처리

**L2. output_json 직렬화 실패 무시**
- objectMapper.writeValueAsString 실패를 빈 catch로 삼킴 → output_json 빈 문자열
- output_json은 프롬프트 개선 근거로 쓸 수 있는 데이터라 버리면 아까움
- 기능 영향은 없음
